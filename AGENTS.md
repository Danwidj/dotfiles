# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.
- Chezmoi's managed source root is `home/`, not the repo root: a root `.chezmoiroot` file (containing `home`) tells chezmoi to treat `home/` as the source state, so `.chezmoi.toml.tmpl`, `.chezmoiignore.tmpl`, `dot_config/`, `private_Library/`, and every `run_once_*`/`run_onchange_*`/`run_after_*` script live under `home/`. Repo tooling (`.github/`, `tests/`, `scripts/`, `justfile`, `README.md`) stays at the repo root and is never applied to `$HOME`. `chezmoi init/apply/diff --source=.` still works unchanged from the repo root — chezmoi auto-detects `.chezmoiroot` regardless of how the source path was passed. Any new chezmoi-managed file must go under `home/`; anything meant to stay repo tooling must NOT go under `home/`.
- Bats tests under `tests/files/*.bats` reach into chezmoi-managed content via raw filesystem paths (not through chezmoi's own root resolution), so those paths need the `home/` segment (e.g. `${BATS_TEST_DIRNAME}/../../home/dot_config/...`) — but the `--source="${BATS_TEST_DIRNAME}/../.."` argument passed to `chezmoi init --apply` itself does NOT need a `/home` suffix, since chezmoi resolves that automatically.
- `scripts/lint.sh` shellchecks both `home/run_*.sh` and `scripts/*.sh` (via `git ls-files`) — keep these globs in sync if the source root or scripts layout ever moves again. Substantial shell logic embedded in `.github/workflows/*.yaml` `run:` blocks should be extracted into `scripts/ci-*.sh` files (see `ci-install-chezmoi.sh`, `ci-install-homebrew.sh`, `ci-chezmoi-apply.sh`, `ci-write-chezmoi-config.sh`) so shellcheck can see it and it's runnable/debuggable locally; trivial one-liners and steps that only make sense inside a real Actions runner (e.g. `$GITHUB_PATH` writes) should stay inline.
- Verifying workflows locally with `act` (`brew install act`) on this Apple Silicon + colima setup has three sharp edges: (1) `act --bind` needs a real non-worktree git checkout — a `git worktree`'s `.git` file points to a gitdir outside the worktree that the container can't see, so `git` commands fail inside act with "not a git repository"; clone the branch to a plain directory first. (2) colima only virtiofs-mounts `$HOME` into its VM by default, so that plain clone must live under `$HOME`, not `/tmp` — a clone elsewhere silently produces an empty/missing mount in the container. (3) `--container-architecture linux/amd64` (needed to match real `ubuntu-latest` runners) emulates x86_64 via QEMU; colima's default 2GiB/2CPU OOM-kills anything non-trivial (bump with `colima start --memory 6 --cpu 4`, then restore after), and Homebrew's Linux install specifically fails under this QEMU emulation ("x86_64 support ... requires SSSE3") — a real GitHub amd64 runner doesn't have this problem, so treat it as an act/QEMU limitation, not a script bug. `act` cannot run `macos-latest` jobs at all; verify macOS-only steps by running them directly on a Mac (sandbox anything that writes to `$HOME`, e.g. via `HOME=$(mktemp -d) ./scripts/foo.sh`, to avoid clobbering the real chezmoi config).
